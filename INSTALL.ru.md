# Установка

[English](INSTALL.md) · Русский

Контроллер ставят вместе с остальным Placitum: он раздаёт конфигурацию узлам и инспекторам и без
них бесполезен. Обычно его поднимает установщик из
[placitum-core](https://github.com/exemt/placitum-core). Здесь — что контроллеру нужно, как он
настраивается и как проверить, что он встал.

## Что нужно рядом

| Компонент | Обязателен | Зачем |
| --- | --- | --- |
| PostgreSQL | да | конфигурация: пространства, серверы, маршруты, профили, черновики |
| NATS с JetStream | да | KV, через который поколения уходят на узлы и инспекторам |
| Внутренний Redis | да | блобы поколений: в KV уходит указатель, тело лежит здесь |
| `crypto` | при сертификатах из панели | расшифровка приватных ключей ключом установки; сам контроллер открытого текста не видит |
| `search` (логгер) | для журнала и инцидентов | панель ходит в него через контроллер, наружу он не открыт |
| `geo` | для карточек адреса | страна и ASN по адресу |

Контроллер может лежать без вреда для трафика: узлы работают по последней применённой
конфигурации.

## Переменные

| Переменная | По умолчанию | Что |
| --- | --- | --- |
| `CONTROLLER_PORT` | `8080` | порт API и панели |
| `CONTROLLER_HOST` | — | адрес, на котором слушать; не задан — все адреса, так и нужно в контейнере. Без Docker ставьте `127.0.0.1` |
| `CONTROLLER_CORS_ORIGIN` | — | origin'ы через запятую, которым можно вызывать API из браузера; не задан — никому. Панели и её dev-серверу он не нужен |
| `CONTROLLER_DATABASE_URL` | `postgres://waf:waf@127.0.0.1:5432/waf` | PostgreSQL |
| `CONTROLLER_NATS_URL` | `nats://127.0.0.1:4222` | NATS |
| `CONTROLLER_NATS_USER`, `_PASS`, `_TOKEN` | — | реквизиты NATS, которые контроллер печатает в конфигурацию узлов |
| `CONTROLLER_REDIS_URL` | — | буфер: контроллер туда не пишет, но печатает его адрес в конфигурацию узлов |
| `CONTROLLER_REDIS_INTERNAL_URL` | как `CONTROLLER_REDIS_URL` | внутренний Redis: блобы поколений |
| `CONTROLLER_NODE_NATS_URL`, `_REDIS_URL`, `_REDIS_INTERNAL_URL` | адреса самого контроллера | адреса NATS и Redis, которые печатаются в конфигурацию узлов, когда узлы ходят к ним не так, как контроллер: например, nginx на машине вне сети контейнеров |
| `CONTROLLER_CRYPTO_SERVICE_URL` | — | `http://crypto:8093` |
| `CONTROLLER_CRYPTO_PUBLIC_KEY` | — | публичная половина ключа установки: PEM или путь к файлу |
| `CONTROLLER_SEARCH_URL` | — | `http://search:8091` |
| `CONTROLLER_GEO_URL` | — | `http://geo:8092` |
| `CONTROLLER_UX_DIR` | `/app/ux/dist` | собранная панель в образе |
| `CONTROLLER_SCHEMA_DIR` | `/app/schema` | схема базы в образе |
| `CONTROLLER_COMPILE_DIR` | `/app/data/compile` | куда компилятор кладёт собранные конфигурации |
| `CONTROLLER_LOG` | `info` | уровень журнала |

Адрес NATS, который контроллер печатает в конфигурацию узлов, берётся из его собственного
окружения, а не из сохранённого документа: сохранение документа не должно менять то, куда ходит
установка.

## Первый запуск

1. **Поднять PostgreSQL** и дать контроллеру `CONTROLLER_DATABASE_URL`.
2. **Схема.** На пустой базе контроллер при первом старте ставит `schema/01-schema.sql` и начальные
   данные `schema/02-seed.sql`. Если схема в базе уже есть, он её не трогает.
3. **Ключ установки.** Публичная половина монтируется контроллеру
   (`CONTROLLER_CRYPTO_PUBLIC_KEY`), приватная — только `crypto` и агентам узлов.
4. **Панель** открывается на `CONTROLLER_PORT`. На свежей установке в ней одно пространство
   `default`, каталог инспекторов и встроенные профили. Серверов и маршрутов нет, их заводит
   оператор.
5. **Каталог гео** (страны и ASN) заливается отдельно: у выгрузки MaxMind своя лицензия, и в
   образ она не входит.

## Docker Compose

```yaml
services:
  controller:
    image: placitum/controller
    ports: ["127.0.0.1:8080:8080"]
    environment:
      CONTROLLER_DATABASE_URL: postgres://waf:waf@postgres:5432/waf
      CONTROLLER_NATS_URL: nats://nats:4222
      CONTROLLER_REDIS_URL: redis://redis:6379
      CONTROLLER_REDIS_INTERNAL_URL: redis://redis-internal:6379
      CONTROLLER_CRYPTO_SERVICE_URL: http://crypto:8093
      CONTROLLER_CRYPTO_PUBLIC_KEY: /run/secrets/waf_node_pub
      CONTROLLER_SEARCH_URL: http://search:8091
      CONTROLLER_GEO_URL: http://geo:8092
    secrets: [waf_node_pub]
    depends_on: [postgres, nats, redis-internal]
```

Своего входа у API нет, поэтому порт опубликован только на 127.0.0.1. Второй путь внутрь —
браузер: запрос, который что-то меняет, и рукопожатие WebSocket получают `403 cross_origin`, если
`Origin` или `Sec-Fetch-Site` называют чужой сайт. Инструменты, которые не шлют ни того ни другого,
проходят. Ответы несут `Content-Security-Policy`, `X-Frame-Options: DENY` и `nosniff`.

## Проверка после запуска

```sh
curl -fsS http://127.0.0.1:8080/healthz

# Панель отдаётся тем же процессом
curl -fsS -o /dev/null -w '%{http_code}\n' http://127.0.0.1:8080/

# База отвечает и схема на месте
psql "$CONTROLLER_DATABASE_URL" -c "select name from http_spaces"
```

На свежей установке в панели пустое дерево конфигурации, каталог инспекторов из процессов, которые
запущены в установке, и профиль `default` у каждой подсистемы. В комплекте десять процессов;
установщик core отмечает запущенные через `PUT /api/<пространство>/inspectors/installed`, а
остальных для панели, маршрутов и сборки нет. `vlai` приходит выключенным. Если панель показывает жёлтое предупреждение про отпечаток
ключа, файл `contour-pin.json` с отпечатком установки не смонтирован и браузер публичный ключ не
сверяет.

## Обновление

Схема на живой базе не обновляется. Новый образ с той же схемой поднимается поверх прежней базы;
если схема изменилась, установка ставится заново, на пустую базу.

## Типичные ошибки

- **Отпечаток ключа зашивается на сборке.** Сменили ключ установки — пересоберите образ, иначе
  панель будет ругаться на несовпадение.
- **Конфигурация в памяти процесса.** Правка в базе руками не видна до перезапуска: контроллер
  держит состояние в памяти и пишет в базу, а не читает её на каждый запрос.
- **`:8091` и `:8093` наружу не выставляют.** В поиск и `crypto` ходит контроллер, не браузер.
