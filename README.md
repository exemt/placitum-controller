# Placitum controller

Панель управления и API Placitum. В панели заводят серверы, маршруты, профили инспекторов и
списки адресов, а контроллер собирает из этого конфигурацию и рассылает её узлам защиты и
инспекторам.

Трафик через контроллер не идёт. Если контроллер остановится, узлы продолжат работать на
последней полученной конфигурации.

Отдельно контроллер обычно не ставят: его вместе со всем остальным поднимает установщик из
[placitum-core](https://github.com/exemt/placitum-core). Этот README о том, как контроллер
устроен, как собрать образ и как с ним работать при разработке.

## Как это работает

Настройки хранятся в PostgreSQL. Когда оператор нажимает в панели «Разослать», контроллер
собирает из них конфигурацию: для узла это конфиг nginx, для инспекторов их профили и правила.
Сама конфигурация кладётся во внутренний Redis, а в NATS JetStream уходит ссылка на неё. Узлы и
инспекторы забирают новую версию оттуда.

Панель и API отдаёт один процесс Node.js. Собранная панель лежит внутри образа, отдельный
веб-сервер не нужен.

## Что нужно рядом

| Сервис | Когда нужен | Зачем |
| --- | --- | --- |
| PostgreSQL | всегда | хранит конфигурацию |
| NATS с JetStream | всегда | через него узлы и инспекторы узнают о новой конфигурации |
| Redis (внутренний) | всегда | в нём лежит сама конфигурация для рассылки |
| `crypto` | для сертификатов из панели | расшифровывает ключи сертификатов; контроллер их в открытом виде не видит |
| `search` | для журнала и инцидентов | поиск по событиям |
| `geo` | для карточек адресов | страна и ASN по IP |

## Настройки

Контроллер настраивается переменными окружения. Основные:

| Переменная | По умолчанию | Что задаёт |
| --- | --- | --- |
| `CONTROLLER_PORT` | `8080` | порт API и панели |
| `CONTROLLER_DATABASE_URL` | `postgres://waf:waf@127.0.0.1:5432/waf` | PostgreSQL |
| `CONTROLLER_NATS_URL` | `nats://127.0.0.1:4222` | NATS |
| `CONTROLLER_REDIS_INTERNAL_URL` | как `CONTROLLER_REDIS_URL` | внутренний Redis для рассылки конфигурации |
| `CONTROLLER_REDIS_URL` | — | Redis-обменник: контроллер в него не ходит, только сообщает адрес узлам |
| `CONTROLLER_CRYPTO_PUBLIC_KEY` | — | публичный ключ контура: PEM или путь к файлу |
| `CONTROLLER_CRYPTO_SERVICE_URL` | — | адрес `crypto`, например `http://crypto:8093` |
| `CONTROLLER_SEARCH_URL` | — | адрес `search`, например `http://search:8091`; без него в панели нет журнала |
| `CONTROLLER_GEO_URL` | — | адрес `geo`, например `http://geo:8092`; без него у адресов нет стран и ASN |
| `CONTROLLER_LOG` | `info` | уровень журнала |

Полный список — в [INSTALL.md](INSTALL.md) и [src/config.ts](src/config.ts).

Контроллер держит конфигурацию в памяти. Если поправить что-то прямо в базе, он увидит это
только после перезапуска.

## Сборка образа

```sh
docker build -t placitum/controller .
```

Или сразу из GitHub, без клона:

```sh
docker buildx build -t placitum/controller "https://github.com/exemt/placitum-controller.git#develop"
```

В панель при сборке зашивается отпечаток публичного ключа контура. По нему браузер проверяет,
что API отдал настоящий ключ. Отпечаток печатает `sh bootstrap/secrets.sh --fingerprint` в
placitum-core, передаётся он так:

```sh
docker build --build-arg VITE_CONTOUR_FINGERPRINT=sha256:… -t placitum/controller .
```

Без отпечатка образ соберётся, но панель будет показывать предупреждение. После смены ключа
образ нужно пересобрать. Установщик core делает всё это сам.

Проверить, что контроллер запустился:

```sh
curl -fsS http://127.0.0.1:8080/healthz
```

## Схема базы

Схема едет в образе, и контроллер накатывает её сам при старте. Пустая база получает поставку
1.0: пространство `default`, справочники, страницы отказа, правила CRS, каталог инспекторов и
профили по умолчанию. Серверов и маршрутов в ней нет, их заводит оператор. В работающей базе
применяются только миграции, которых ещё нет в журнале `waf_schema_log`. Несколько копий
контроллера за миграции не подерутся: накатчик берёт блокировку в PostgreSQL.

Посмотреть, что применится, ничего не меняя:

```sh
npm run migrate:check
```

Миграции идут только вперёд: если откатить образ, схема не откатится. Что лежит в поставке и
как добавить миграцию, описано в [schema/README.md](schema/README.md).

Каталог стран и ASN (GeoLite2) в поставку не входит, у выгрузки MaxMind своя лицензия. Её
загружают через панель или командой `npm run load-geo`.

## Безопасность

- Сам контроллер пароль не спрашивает. В полной установке панель открывают через узел защиты,
  где стоит вход, а порт контроллера слушает только 127.0.0.1. Не публикуйте этот порт наружу
  и не ставьте перед ним прокси.
- Контроллеру передают только публичную половину ключа контура, приватную он не примет.
- Порты `search` (8091) и `crypto` (8093) наружу не открывают: в них ходит контроллер, а не
  браузер.

## Разработка

Нужен Node.js 22.18 или новее: контроллер запускается прямо из исходников TypeScript, без
сборки.

Для работы нужны PostgreSQL, NATS и Redis. Проще всего взять их из
[placitum-core](https://github.com/exemt/placitum-core): поставьте в его `.env`
`PLC_INFRA_PORTS=loopback` и запустите `./install.sh infra`. Сервисы откроются на 127.0.0.1, и
умолчания контроллера уже смотрят туда. Остаётся указать Redis:

```sh
npm ci
CONTROLLER_REDIS_URL=redis://127.0.0.1:6379 CONTROLLER_REDIS_INTERNAL_URL=redis://127.0.0.1:6380 npm run dev
```

API поднимется на http://127.0.0.1:8080 и будет перезапускаться при правках.

Панель с горячей перезагрузкой запускается отдельным процессом:

```sh
npm ci --prefix ux
npm run ux
```

Она откроется на http://localhost:5173 и будет отправлять запросы `/api` в контроллер на :8080,
поэтому контроллер должен быть запущен. Отпечаток ключа dev-сервер берёт из
`VITE_CONTOUR_FINGERPRINT` в `ux/.env` или в окружении, без него панель покажет предупреждение.
Чтобы контроллер сам отдавал панель на :8080, соберите её: `npm run ux:build`.

Проверки:

```sh
npm run typecheck
npm test
```

Часть тестов требует поднятой базы, поэтому ни CI, ни сборка образа тесты не запускают. CI на
каждый push в `develop` и на pull request проверяет типы, собирает панель и образ.

## Что где лежит

```
src/            API, сборка и рассылка конфигурации, состояние узлов
ux/             панель: React, Vite, MUI
ux/help/        справка администратора, которую показывает панель
schema/         схема базы: поставка 1.0 и миграции
data/crs-src/   исходные файлы правил CRS, из которых собрана поставка
```
