# placitum/controller

Панель и API Placitum: здесь заводят серверы, маршруты, профили инспекторов и списки, отсюда
конфигурация уезжает на узлы защиты.

Контроллер — плоскость управления. Трафик через него не идёт: узел, потерявший контроллер,
продолжает работать по последней применённой конфигурации, и это осознанное свойство, а не
везение.

```
оператор ──► панель (React) ──► API ──► Postgres: черновик
                                  │
                                  ├─► компилятор: конфиг nginx из документов пространства
                                  └─► JetStream KV ──► агенты узлов и инспекторы
```

Один процесс отдаёт и API, и собранную панель: `CONTROLLER_UX_DIR` указывает на статику внутри
образа, отдельного веб-сервера не нужно.

## Что здесь лежит

| Каталог | Что это |
| --- | --- |
| `src/` | API, компилятор конфигурации, каналы раскатки, сходимость, поиск-прокси |
| `ux/` | панель: React и Vite, справка администратора в `ux/help` |
| `schema/` | поставочная база: структура, данные поставки, архив миграций, стендовое дерево |
| `docs/` | устройство контроллера и соглашения панели |

## Сборка и запуск

```sh
docker build -t placitum/controller .
docker buildx build -t placitum/controller "https://github.com/exemt/placitum-controller.git#develop"
```

Отпечаток ключа контура зашивается в панель на сборке (`--build-arg VITE_CONTOUR_FINGERPRINT=`):
по нему браузер сверяет публичный ключ, который вернёт API. Без него сборка пройдёт, но панель
покажет предупреждение, что сверка выключена.

Что нужно рядом, переменные и порядок первого запуска — [INSTALL.md](INSTALL.md).

## Схема базы

Схема едет в образе (`/app/schema`): структура, данные поставки и архив миграций. Пустая база
поднимается поставкой 1.0 — одно пространство, справочники, страницы отказа, CRS, каталог
инспекторов и неуничтожимые профили `default`; серверов, путей и сертификатов в ней нет,
конфигурацию заводит оператор.

**Накатчика для живой установки пока нет** — он в работе; до тех пор миграции после поставки
применяются руками. Что он обязан уметь и почему живёт именно здесь, а не в фундаменте
установки, описано в `core/migrate/README.md` репозитория `placitum-core`.

## Разработка

```sh
npm ci && npm run dev            # API на :8080
npm run ux                       # панель отдельным dev-сервером на :5173
npm run typecheck
npm test                         # часть набора требует поднятой базы
```

Тесты в сборке образа не гоняются намеренно: `src/*-http.test.ts` и сверка канона профилей
требуют базы и фикстур платформы, то есть контура, а не контекста сборки.

## Ветки

`develop` — то, что разрабатывается: сюда приезжает каждая выкладка. `main` — выкаченные сборки.
Правок в этом репозитории не делают: обе ветки производные от платформы.
