# События безопасности

Раздел «События безопасности» — лента решений по запросам. Сюда смотрят каждый день: здесь видно,
что система заблокировала, почему именно и кто из инспекторов это решил.

## Что регистрируется

Событие безопасности — запись о решении по одному запросу, ответу или кадру. Записывает её модуль,
и записывает всегда, независимо от вердикта: пропущенный запрос попадает в ленту так же, как
заблокированный. Событие отличается от строки журнала тем, что журнал говорит «запрос был», а
событие — «вот что мы про него решили и на каком основании».

По умолчанию лента показывает последние 24 часа и все вердикты: отбор по вердикту задаётся вручную.

## Список событий

Колонка за колонкой:

| Колонка | Что в ней |
| --- | --- |
| **Время** | когда решение принято, в часовом поясе браузера |
| **Ray** | сквозной идентификатор запроса. По нему объект прослеживается от буфера до архива, и по нему же ищутся парные записи других фаз |
| **IP / CIDR** | адрес клиента; рядом — страна и сеть провайдера, если у установки есть гео |
| **Вердикт** | `allow`, `deny` или `redirect` |
| **Счёт** | сумма вкладов инспекторов на этой фазе |
| **Фаза** | запрос, ответ или кадр |
| **Метод**, **Host**, **URI** | что именно запрашивали |
| **Код** | слева — код, отданный клиенту, справа — код приложения. Если они разошлись, ответ приложения закрыт нами |
| **Инспекторы** | чипы получателей: имя, вердикт, счёт, задержка |
| **Пользователь** | пользователи сессий, которых назвала проверка входа: `источник:логин` |
| **Маркер** | метки, которые повесили инспекторы: по клику — фильтр по метке |

Строки сортируются по времени. Автообновления нет: список берётся на момент запроса, кнопка
**Обновить** перечитывает его.

В шапке колонки **Время** к окну отбора приставлены две кнопки. Стрелка задаёт порядок: **«↓»** —
новые сверху (так журнал открывается), **«↑»** — старые сверху, и стрелка при этом подсвечивается.
Порядок — не сортировка показанной страницы: страницу режет хранилище, и в восходящем порядке
листаются те же записи с начала окна. Смена порядка возвращает на первую страницу.

Вторая кнопка, **«››»**, дописывает к секунде миллисекунды: `09-10 14:23:45` становится
`09-10 14:23:45.123`, **«‹‹»** сворачивает обратно. На секунде запрос и его ответ, а тем более
десяток кадров WebSocket, встают одним штампом, и порядок внутри неё читается только так.

В шапке колонки **Ray** стоит переключатель **«‹‹»**: он жмёт ray до последнего блока —
`cea99b02-15a0-4a1c-b63f-73712e1c15ab` показывается как `73712e1c15ab`. Строки различаются как раз
хвостом, а колонка при этом отдаёт списку около 120 пикселей. Это только показ: по клику в фильтр
уходит ray целиком, полное значение видно по наведению, а **«››»** возвращает его в таблицу.

### Какие колонки показывать

Чип **«колонки»** у правого края секции «группировка» открывает список колонок с галочками. Время и
ray стоят всегда; остальные можно снять. Колонка, по которой стоит фильтр, показывается вопреки
выбору и помечена «в фильтре»: условие без колонки нечем ни прочитать, ни снять. Выбор помнит
браузер, к установке он не относится.

У каждой колонки есть своя минимальная ширина. Шире — по содержимому, уже — никогда: раньше
колонка с коротким значением (вердикт, фаза, код) сжималась уже собственного поля отбора, и то
вылезало на соседнюю. Когда сумма минимумов не влезает в окно, таблица уходит в горизонтальную
прокрутку; вернуть её в один экран — дело выбора колонок.

## Фильтрация

Над таблицей — **окно времени** и поля отбора: ray, адрес или подсеть, метод, host, uri, код,
вердикт, инспектор, фаза, пользователь, маркер.

### Строка запроса

Самая верхняя полоса собирает все условия отбора в одну фразу: `time = 24h and verdict = deny and
ip = 10.0.0.1 and uri ~ "/api"`. Поля разнесены по шапке таблицы, свёрнутой секции поиска и
групповой панели, и целиком условие иначе нигде не видно.

Строку можно править вручную. Поставьте курсор — под ней откроется подсказка: сначала поля, потом
сравнения, которые это поле принимает, потом значения. Для окна времени, вердикта, метода, фазы,
серверов, маршрутов и инспекторов значения известны заранее. Для адреса, host, uri, кода,
пользователя, маркера, страны и ASN подсказка показывает самые частые значения за выбранное окно
с числом записей — с учётом остальных условий строки. `ip =` после `verdict = deny` покажет, кого
блокировали чаще всего.

| Клавиша | Что делает |
| --- | --- |
| `↑` `↓` | выбрать подсказку |
| `Tab` | вставить подсказку |
| `Enter` | найти; если подсказка выбрана — вставить её |
| `Esc` | закрыть подсказку; ещё раз — вернуть применённый запрос |
| `Ctrl+Пробел` | открыть подсказку снова |

Поиск идёт по `Enter`, а не по мере набора. Пока запрос изменён и не применён, рамка строки
жёлтая, справа — кнопка **найти**. `Enter` на прежнем запросе повторяет поиск и сдвигает окно
времени к текущей минуте. Крестик возвращает применённый запрос, а когда править нечего —
**сбрасывает фильтры**.

Знак говорит, как поиск сравнивает на самом деле:

| Знак | Что значит | Где |
| --- | --- | --- |
| `=` | совпадение целиком | host, код, вердикт, метод, фаза, инспектор, пользователь, маркер, страна, ASN, ray, `header.имя`, `param.имя` |
| `~` | подстрока без учёта регистра | uri, body |
| `in [a, b]` | любое из списка | адреса и подсети, серверы, маршруты; окно времени, заданное датами |
| без знака | ключ есть, значение любое | `header.имя`, `param.имя` |

Значение с пробелом, запятой или знаком сравнения берут в кавычки: `marker = "bot farm"`. Окно по
датам — `time in ["2026-09-16 10:00", "2026-09-17 12:00"]`; дата без времени значит весь день.
Маршрут пишется так, как он назван в панели: `route = "shop.example /api"`. Строки `time` в
запросе может не быть — тогда окно 24 часа.

Условия соединяет только `and`. `or`, `not`, скобок и сравнений `!=`, `>`, `<` поиск не умеет —
строка так и скажет. Несколько значений одного поля задают списком: `ip in [a, b]`. Заголовок и
параметр — по одному условию на запрос.

Ошибку строка подчёркивает красной волной и объясняет под собой: нет такого поля, полю не
подходит сравнение, `203.0.113.300` — не адрес, код — не три цифры. Клик по объяснению выделяет
ошибочное место. Пока ошибка есть, поиск не запускается и таблица показывает прежний запрос.
То, что вы ещё набираете, строка не ругает — только то, что осталось позади курсора, и всё
целиком по `Enter`.

### Сохранённые фильтры

Звезда в правом конце строки открывает сохранённые фильтры. Назовите запрос и нажмите
**сохранить** — он появится в списке; то же имя ещё раз — **обновить**. Клик по фильтру применяет
его. Когда применённый запрос совпадает с сохранённым, его имя стоит в начале строки, а звезда
закрашена.

Окно вроде `time = 24h` сохраняется как есть и каждый раз считается от текущей минуты; окно по
датам остаётся теми же датами. Ниже списка — **недавние**: восемь последних применённых запросов.

Фильтры хранятся в браузере, отдельно для каждого пространства: на другом компьютере и у другого
оператора их не будет. Если маршрут из сохранённого фильтра удалили, строка покажет ошибку и
ничего не применит.

Знак вопроса рядом — шпаргалка по записи и примеры; клик по примеру кладёт его в строку.

**Пользователь** — из сессии, которую на запросе назвала проверка входа: своя сессия установки,
чужой JWT или кука приложения. Пишется парой **`источник:логин`** — `corp:alice`. Источник входа и
есть пространство имён: `alice`, вошедшая через проверку входа установки, и `alice` из чужого токена
совпадают именем и больше ничем, и слить их в одного человека журнал не вправе.

Поле принимает обе формы. `corp:alice` — «этот человек»; голый `alice` — «этот логин у кого
угодно», по всем источникам сразу. Двоеточие делит по первому вхождению, поэтому логин, в котором
двоеточие есть, ищут с пустым источником: `:urn:user:1`.

Колонка «пользователь» показывает пользователей строки — их бывает несколько, когда на запросе сошлись
две сессии (проверка входа установки и подсмотренная кука приложения). Звёздочка — подпись токена не
проверялась, и логин там написал сам клиент. По клику включается фильтр ровно на этого пользователя.

Той же парой **группируют**: ось «пользователь» отвечает на «кто ходил чаще всех» и «у кого больше
всего блокировок» — с колонкой deny рядом это готовый список тех, кем стоит заняться. Запись без
сессий в группировку не попадает вовсе; запрос с двумя сессиями считается в обеих группах. Клик по
группе разворачивает её в те же строки.

**Маркер** — метка, которую инспектор повесил на событие действием «Добавить маркер» (профиль
инспектора, раздел «Что сделать»). Строку придумывает оператор: «bot-farm», «инцидент-42»,
«ручная проверка», — и по ней потом собираются все такие события разом, независимо от того, кто их
пометил и по какой причине. Совпадение точное, строкой целиком.

Маркер удобен как ось **группировки**: «каких меток сколько за сутки» отвечается одной группой,
а не перечислением инспекторов и кодов. События без меток в такую группировку не попадают.

Сворачиваемая секция **«поиск в запросе»** ищет по содержимому фрагмента. Галочки справа — какие
поля показывать: **заголовок**, **параметр**, **тело**; отмеченное поле раскрывает секцию, снятое
стирает своё условие. Внутри:

- `заголовок` или `заголовок=значение`;
- `параметр` или `параметр=значение`;
- подстрока в теле.

Свёрнутая секция держит набранное чипами, крестик на чипе снимает условие, а рядом с названием
секции горит точка. Клик по паре в фрагменте карточки кладёт её в то же поле и отмечает его, если оно
было снято.

Важно: этот поиск идёт по **фрагменту** запроса, а не по архиву. Чего в фрагменте нет, того он не найдёт —
см. [«Фрагмент запроса»](#фрагмент-запроса) ниже.

Значения в таблице кликабельны: нажатие на адрес, инспектора или код ставит фильтр по этому
значению, повторное — снимает.

## Группировка

Секция **«группировка»** сворачивает отфильтрованные строки в группы. Пунктирные чипы с плюсом —
оси, которые можно добавить: адрес, host, сервер, uri, маршрут, метод, код, вердикт, фаза, маркер,
пользователь. Добавленные оси встают слева цепочкой со стрелками: первая ось — первая колонка
таблицы групп, и так далее; крестик на чипе снимает ось, последняя снятая возвращает таблицу
списком.

Секция сворачивается, как и поиск по запросу. В свёрнутой шапке остаётся та же цепочка осей, с теми
же крестиками — по чему свёрнута таблица, видно и снимается без разворота, — а справа счёт групп и
выбор колонок. У непустой секции рядом с названием горит точка.

У таблицы групп свои колонки: значения осей, число запросов, исходы и последний запрос. Число
запросов стоит на полоске: её длина — доля от самой крупной группы страницы, так что какая группа
крупнее, видно формой, а не сравнением длинных чисел. **Исходы** — вторая полоска, из трёх частей:
allow зелёным, redirect жёлтым, deny красным, в долях от запросов группы. Точные числа приходят по
наведению; часть, которой досталось меньше двух пикселей, всё равно рисуется — единственный deny на
сотню тысяч запросов иначе исчез бы совсем. Остаток полоски пуст, когда у части записей вердикта
нет вовсе. Заголовки
сортируют. Клик по группе кладёт её значения в фильтры и возвращает список ровно тех строк, из
которых она сложена.

В групповом виде появляется третья секция — **«фильтры»**. Это те же поля отбора, что в списке
стоят над колонками: группируется уже отобранное, и менять условие не должно требовать возврата к
списку. Секция сворачивается, как и две соседние: свёрнутая держит отобранное чипами, крестик на
чипе снимает условие, а рядом с названием горит точка. Полностью, вместе с поиском по фрагменту,
условие читается в строке запроса наверху.

## Карточка события

Строка разворачивается в карточку. Слева — как принято решение, справа — что было в запросе.

### Итог модуля

Первая, несворачиваемая строка карточки: вердикт, фаза и причина одной фразой — «заблокировано по
таблице», «заблокировано модулем по таймауту волны», «разрешено». Отдельно помечается, решил ли
запрос инспектор или сам модуль.

### Получатели фазы

Ниже — раскрывающийся список инспекторов, которых вызывали на этой фазе. В шапке каждого: вердикт со счётом,
имя, набор правил (`профиль`) и время ответа. Внутри — находки этого инспектора в его собственном
виде: у правил обработки трафика это сработавшие правила с местом совпадения (`header`, `cookie`,
`uri`, `args`, `body`) и смещением, у IP фильтра — по какому списку сработало (чёрный список,
гео, «вне списка»), у остальных — их собственные поля.

Инспектор, чей вклад перевёл счёт через порог или вынес прямую блокировку, помечен как **решающий**.
Получатель с вердиктом `allow` и без находок не раскрывается: раскрывать нечего.

Если инспекторов на записи нет вовсе, карточка так и говорит: к записи они не привлекались.

### Сессии

Чьи сессии увидели инспекторы на этом запросе. Строка на сессию: пользователь `источник:логин`, вид
(своя, JWT, приложения), инспектор, который её назвал, идентификатор. Идентификатор — не кука: у своей сессии
это её номер, у JWT — поле токена либо отпечаток, у куки приложения — хеш. Пометка «подпись не
проверена» — токен разобран без ключа; «отправитель пассивен» — проверка входа вызывалась в пассивном
режиме, заголовки пользователя приложению не ставились.

Секции нет, когда сессий не было: на маршруте нет проверки входа либо клиент пришёл без входа.

### Автодействия

Если инспекторы обменивались сигналами, в карточке появляется блок **Автодействия**: кто просил,
кого, о чём — и что из этого вышло.

| Исход | Что произошло |
| --- | --- |
| **применено** | получатель сигнал выполнил целиком |
| **нет правила** | у получателя нет правила приёма для этого отправителя |
| **нет веса в профиле** | правило есть, но вклад отправителя в наборе правил не задан |
| **нет счётчика для этой оси** | просили изменить счётчик по оси, которой у получателя нет |

Отдельно помечаются сигналы, которые вообще не ушли: **не доставлено — отправитель пассивен**
(пассивный инспектор в решение не вмешивается) и **нет правила у получателя**.

### Маркеры

Метки, которые повесили на это событие. Клик по метке ставит фильтр — так из одного события
разворачивается вся его группа. Кто именно пометил и по какой причине, видно выше, в
**Автодействиях**: маркер — множество, и одна и та же метка от двух инспекторов остаётся одной.

Секции нет, когда меток не было.

### Фрагмент запроса

Правая панель карточки — то, что модуль снял с запроса: **заголовки**, **параметры**, **тело**.
У каждой вкладки указан объём.

Фрагмент — не архив. В него намеренно не входят `authorization`, `cookie`, `proxy-authorization` и то,
что запрещено на маршруте. Если вкладка пуста, панель объясняет, почему именно: заголовков не было;
заголовки были, но все запрещены; тела в фрагменте нет, потому что фрагмент тела на маршруте не назван —
по умолчанию он выключен, и тогда тело ради записи не читают.

Длинные значения урезаются: панель помечает, что показаны первые N байт, что значение срезано
пределом на пару или что пары выброшены, потому что имя заняло больше половины предела.
Двоичное содержимое показывается в base64.

### Оригинал

Оригинал — несмаскированный объект целиком, в отличие от фрагмента. Строка состояния в карточке
говорит, где он:

- **в буфере** — ещё в горячем хранилище, с именем буфера;
- **в архиве** (и до какой даты) — ушёл в S3 после вердикта;
- **уже отпущен буфером** — срок в буфере истёк, в архив не увозили;
- **не сохранялся** — на маршруте не был назначен ни архив, ни оригинал в буфере.

Пока оригинал доступен, его можно посмотреть и скачать прямо из карточки. Когда локатора уже нет,
кнопки выключены.

### Парная запись

У запроса и ответа один `ray` и две записи. В карточке есть переход к записи другой фазы —
«к записи фазы: ответ».

## Причины блокировки

Причина в карточке и код в аудите — одно и то же, названное словом и машинно.

| Причина | Код | Кто закрыл |
| --- | --- | --- |
| скоринг | `score` | модуль: счёт дошёл до порога маршрута |
| блок по таблице | `local_list` | локальный слой: адрес в списке |
| внутренний блок | `local_rate` | локальный слой: ограничитель частоты |
| инспектор | `inspector` | инспектор вынес прямой `deny` |
| таймаут волны | `fail_timeout` | модуль: волна не уложилась в дедлайн |
| инспектор не ответил | `fail_absent` | модуль: обязательный инспектор промолчал |
| сбой шины | `fail_bus` | модуль: сообщение не удалось опубликовать |
| тело недоступно | `fail_body` | модуль: инспектору нужно было тело, а положить его не удалось |
| сбой инспектора | `fail_inspector` | инспектор ответил «проверить не смог» вместо вердикта |

Первые четыре — решение по существу. Последние пять — исход по «Сбоям проверок»: установка не смогла
получить мнение и закрыл запрос сам. Если таких записей много, разбираться нужно не с правилами, а с
дедлайнами, инспекторами и шиной — см. [«Решение проблем»](13-troubleshooting.md).

## Ложное срабатывание

Событие, где `deny` выставлен по правилу, а запрос был законным, лечится не здесь, а в наборе
правил инспектора: правило отключают, сужают или добавляют исключение. Карточка даёт всё, что для
этого нужно: имя правила, место совпадения и набор правил, по которому инспектор работал.

## Ограничения

Поиск идёт по хранилищу событий; если оно недоступно, лента сообщает «Поиск недоступен» и
не показывает пустую таблицу вместо ошибки.

Отчёты о событиях безопасности пока не делаются.
