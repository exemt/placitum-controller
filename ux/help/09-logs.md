# Журналы

Раздел «Журналы» показывает две разные вещи в одной ленте: строки запросов и ошибок с узлов nginx
и журнал процессов контура — агентов, инспекторов, сервисов.

Не путать с [событиями безопасности](08-events.md): там записано, **что контур решил** по запросу,
здесь — **что произошло** в самих процессах.

## Что попадает в ленту

| Источник | Что пишет |
| --- | --- |
| **nginx на узле** | строки `access_log` — по строке на запрос |
| **nginx на узле** | строки `error_log` — ошибки и предупреждения, в том числе там, где запроса не было вовсе: перезагрузка, недоступный защищаемый сервер |
| **агент** | своя работа: приём конфигурации, проверка, перезагрузка nginx, выгрузка в архив |
| **инспекторы** | своя работа: применение наборов правил, ошибки, перегрузка очереди |

Строки собирает агент узла и отправляет по шине; лента читает их из хранилища событий.

## Колонки и фильтры

- **Время** — когда строка записана.
- **кто записал** — узел или процесс.
- **сервис** — тег писателя. Для строк nginx это тег приёмника, заданный в настройках журналов.
- **уровень** — уровень журналирования (`error`, `warn`, `info`, …). Не путать с уровнем опасности
  события безопасности: это разные шкалы про разные вещи.
- **подстрока в тексте** — поиск по содержимому строки.

Окно времени — общее для всех лент панели.

## Куда пишет nginx

Приёмники настраиваются на любом уровне конфигурации — пространство, виртуальный сервер, маршрут —
и наследуются вниз. Ключ есть — он заменяет родительский целиком, как в nginx.

Два вида приёмника:

- **сокет агента** — единственная дорога, по которой строка попадает в раздел «Журналы». У него
  есть тег, и этот тег становится колонкой «сервис».
- **файл** — путь на узле. Виден только на самом узле; в панель такие строки не попадают.

Приёмников может быть несколько: на краю это обычно сокет агента и файл рядом.

Для `access_log` дополнительно настраиваются формат (из каталога форматов контура; пусто —
`combined`) и условие: строка пишется, только когда заданная переменная не пуста и не равна нулю.
Отдельно есть `access_log off` — им глушат журнал на служебных маршрутах вроде проверки живости.

Для `error_log` настраивается уровень: строки ниже него не пишутся.

## Журнал аудита

Действия операторов и системные операции — кто что создал, изменил, удалил и разослал — пишутся
отдельно от журналов процессов.

> **Не написано.** Просмотр журнала аудита в панели и его настройка будут описаны здесь вместе с
> разделом [«Администрирование»](11-admin.md).

## Отправка во внешние системы

Планируется отдельный потребитель потока аудита для SIEM: со своей подпиской, своим сроком хранения
и своим форматом конверта. На момент написания раздела он не реализован.
