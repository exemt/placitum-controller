# Второй фактор

Ставит перед приложением проверку входа входа. Приложение продолжает проверять своих пользователей само;
система добавляет ещё одну проверку — ту, которую задал администратор: список логинов установки,
одноразовый код, каталог LDAP или домен NTLM. Для пользователя это второй фактор, для приложения —
прозрачный заголовок с именем вошедшего.

Настраивается в «Инспекторы → Второй фактор»: две вкладки, «Источники входа» и «Профили».

## Что он решает

Для модуля это обычный инспектор, который отвечает `allow`, `redirect`, `deny` или `error`. Счёта у
него нет: «вошёл или нет» — вопрос двоичный.

| Вердикт | Когда |
| --- | --- |
| `allow` | сессия цела и допуск есть; приложению уходят заголовки с именем пользователя |
| `redirect` | клиента уводят на форму входа либо на продление сессии |
| `deny` | сессии нет, а форму этому запросу не показывают; либо вошёл не в ту дверь |
| `error` | проверить нечем: неизвестный профиль, недоступный список сессий |

Инспектора спрашивают **на каждом запросе маршрута**. Прежний быстрый путь — условие на маршруте по
куке, — которым проверку входа обходили на крае, умер: он не проверял ни подпись, ни привязку, ни группы, а
на закрытой зоне не проверял бы и допуск.

## Источник и профиль

Сущностей две, и объявляются они в этом порядке.

| | Что описывает | Где |
| --- | --- | --- |
| **источник входа** | сам вход: чем проверяем пароль, где форма, какая кука, сколько живёт сессия, что рассказываем приложению | вкладка «Источники входа» |
| **профиль** | политику одного маршрута: кому показывать форму, кого пускать после входа, чьи сигналы слушать | вкладка «Профили» |

Профиль ссылается на источник ключом «Источник входа», и это ссылка обязательная. На маршруте стоит
профиль: его имя называет `profile=` в объявлении инспектора.

**Источник и есть пространство сессий.** У него ровно одна форма и ровно одна кука, и сессия несёт
его имя внутри себя. Профили одного источника принимают сессии друг друга; профили разных
источников независимы, что бы ни было написано в их куках, — общее пространство склеивает явная
ссылка, а не совпадение строк в двух местах. Чужая кука отвечает одним кодом, чужой источник при
совпавшей куке — другим, и в событии это видно.

Отсюда два типовых приёма, ради которых разрез и сделан:

- **закрытая зона** — второй профиль на **тот же** источник с группами допуска. Второй формы и
  второго входа не нужно: человек уже вошёл, проверяется только членство;
- **спутник для API** — второй профиль на тот же источник, у которого список методов «кому
  показываем форму» пуст: всем без сессии блокировка, никого никуда не уводим.

## Откуда берётся сессия

Первая строка источника — способ, и способов три. Отличаются они не настройкой, а тем, **кто выдал
сессию**, поэтому и поля у них разные: форма показывает только строки выбранного способа.

### Вход через WAF

Контур сам показывает форму, проверяет пароль и выписывает куку сессии. Вторая строка выбирает, чем
проверяется пароль:

| Чем проверяем | Что это |
| --- | --- |
| **Список установки** | логин и пароль из набора строк вида `login:bcrypt[:группы]` |
| **Одноразовый код** | TOTP из приложения-аутентификатора либо общий код доступа |
| **Каталог LDAP** | пароль проверяет каталог организации операцией bind |
| **Домен NTLM** | пароль проверяет контроллер домена |

Провайдер у источника **один**. Пароль плюс код — это не переключатель, а два источника и две
проверки входа на одном маршруте: сперва с паролем, следом с кодом. Второй источник в поле «Личность из
источника» называет первый — так код проверяется для того, кто уже вошёл паролем.

Дальше идут секции: **Форма входа** (сервер, его локейшен, заголовок, пояснение, своя вёрстка),
**Сессия** (кука, срок, продление, привязка), **Активные сессии**, **Приложению** и **Дополнительно**
(защита формы от перебора).

### Чужой JWT

Токен выдал другой издатель. Секции идут по вопросам:

- **Токен** — где он лежит: кука либо заголовок со схемой (`Bearer` для `Authorization`);
- **Проверка** — алгоритм и ключ, издатель, аудитория, допуск по времени на расхождение часов;
- **Поля токена** — какие claims считать логином, идентификатором сессии, группами и сроком. Путь
  через точку вида `data.email` работает.

Своей куки, формы и набора активных сессий у этого способа нет вовсе: сессию выписал не WAF.

Алгоритм `none` разбирает токен **без проверки подписи**: поля написал клиент. Это атрибуция для
журнала, а не защита, и такая сессия в записях помечена.

### Сессия приложения

Кука самого приложения, которой проверка входа верит после того, как **подсмотрела вход**. Секции:

- **Кука приложения** — какую куку приложение выдаёт вошедшему;
- **Как узнаём вход** — адрес и метод входа приложения, откуда брать логин (поле формы, поле JSON,
  параметр строки запроса или заголовок), коды успеха, необязательная проверка поля JSON ответа;
- **Выход** — адрес, успешный ответ на котором снимает доверие;
- **Доверенные сессии** — активный набор строк, куда ложится хеш куки с логином.

Флажок **«Только новая кука»** здесь не украшение: приложение, которое ставит куку и на неудачном
входе, иначе подписало бы чужой логин сессии атакующего.

Удаление записи из набора лишает куку доверия — это и есть выход, сделанный снаружи.

## Форма входа и как её показывают

Форма живёт на локейшене выбранного сервера. Маршрут формы инспекторов не вызывает — вход не должен
требовать входа, — и этот адрес внесён в список разрешённых целей редиректа.

Поле **«Как показать форму»** выбирает одно из двух:

| Способ | Что происходит |
| --- | --- |
| **редирект** | браузер уводится на адрес формы кодом 30x. За терминатором TLS или нестандартным портом адрес может уйти |
| **телом ответа** | инспектор берёт форму у сервиса входа и отдаёт её ответом на тот же адрес с кодом ответа блокировки. Клиент никуда не уходит |

**«Методы, которым показываем форму»** — только эти запросы получают форму. Остальные получают 401 с
ответом блокировки: тело запроса форму всё равно не переживёт.

**«Только HTML»** отсеивает фоновые запросы: форма уходит тому, кто запрашивает страницу. `GET` из
`fetch` за JSON — и запрос вовсе без `Accept` — получают 401, потому что вёрстка формы вместо
ожидаемого JSON сломала бы клиента точно так же.

**Публичный путь делается маршрутом, а не списком.** Списка исключений у проверки входа нет намеренно:
путь, который должен быть открыт, открывают тем, что не вызывают на нём инспектора. Список в профиле
стоил бы сообщения на шину и ответа на каждой пробе здоровья, а вердикт был бы тот же `allow` — и,
что хуже, держал бы второе место, где решают, что публично.

## Допуск: кого пускать после входа

Секция «Допуск» профиля. Пусто — довольно самого входа.

**Группы допуска.** Вошедший обязан состоять хотя бы в одной. Чужой по группе получает 403 и
отдельный ответ блокировки: тот, что выше, говорит «войдите», этот — «вошли, но не сюда». На форму такой
запрос не уводят ни при каком методе — уводить некуда, он уже вошёл.

Группы приходят **в сессии, со входа**. Это снимок на момент входа: вычеркнутый из группы человек
сохраняет доступ до следующего входа — либо теряет его сразу, если завершить его сессию.

## Сессия: кука и список

Механизм один, и называется он «кука и список». Подпись куки доказывает, что сессию выписали мы;
запись в активном наборе — что её не завершили.

```
запись есть      → пропустить
записи нет       → сессия завершена: навигацию на форму, остальным блокировка
набора не видно  → «проверить не смог»: ни закрыто, ни открыто
```

Секция «Активные сессии» источника называет активный набор строк, отдельную короткую куку и срок
записи. В наборе лежит идентификатор сессии, а не сам токен: токен — сотни байт, идентификатор —
тридцать два знака, и при двадцати тысячах активных сессий это разница между десятью мегабайтами и
полумегабайтом на каждом узле.

**Удаление записи — единственный способ завершить сессию снаружи.** Выход в форме, кнопка в панели и
скрипт разбора инцидента делают ровно одно и то же действие. Повод записи несёт логин, поэтому набор
в панели читается как список вошедших, и видно, чью сессию завершаешь.

**Окно на доезд** (умолчание — две секунды) закрывает гонку: запись подтверждена, но дельта до узлов
уходит ещё миллисекунды. Сессия моложе окна проходит по одной подписи — выписать «свежую» сессию, не
зная ключа, нельзя.

**Продление.** У сессии есть точка продления. После неё инспектор на навигационном запросе уводит
клиента на продление: старый токен проверяется, выписывается новый, клиент возвращается назад.
Пароль при этом не спрашивают — это перевыпуск действующей сессии, а не вход. Один лишний редирект
на окно продления; ноль в поле выключает механизм, и тогда по истечении срока человек входит заново.

**Привязка** вшивается в куку: украденная с другой сети или из другого браузера не пройдёт.
Привязывают к подсети, а не к адресу, — мобильные сети меняют адрес в течение сессии.

### Чем платим за список

- **Набор обязан быть доступным.** Он истина, и невидимый набор означает, что жив ли этот вход,
  сказать нечем: проверка входа отвечает «не смог», а исход выбирает маршрут. Раньше сторону размена
  выбирала сама проверка входа, и отставшее зеркало уводило на форму всех разом.
- **Переполнение набора убивает вход.** За пределом набора запись не появляется, и сессия кончится
  вместе с окном на доезд. Потолок набора — это потолок одновременно вошедших, и выбирать его надо с
  запасом.

## Что уходит приложению

На `allow` инспектор выставляет заголовки запроса — единственное переопределение, которое модуль на
этом вердикте применяет. Имена задаются в секции «Приложению»:

| Что | По умолчанию |
| --- | --- |
| логин вошедшего | `X-WAF-User` |
| группы через запятую | `X-WAF-Groups` |
| пройденные факторы | `X-WAF-Auth` |

Там же — необязательная **кука удостоверения**: то же самое, но читаемое приложением самостоятельно,
без доверия заголовкам.

**Заголовки выставляются всегда, даже пустыми.** Снять заголовок на фазе запроса модуль не умеет,
поэтому единственный способ обезвредить `X-WAF-User: admin`, присланный клиентом, — перезаписать
его. Из этого следует правило для маршрутов **без** проверки входа: приложение не должно доверять этим
заголовкам там, где её нет. Надёжнее закрыть вопрос в конфигурации сервера, обнулив заголовок на
таких путях.

**Соседям пользователь передаётся не заголовком.** Правки заголовков ложатся в запрос после всех волн фазы —
инспектор, спрошенный позже, увидел бы в копии то, что прислал клиент. Поэтому пользователь доходит до
соседей отдельной секцией сообщения, и модуль возвращает её в следующих волнах и фазах. Так,
например, счётчик ключует бакет логином вместо куки — и для этого проверка входа обязана стоять на том же
маршруте **раньше** него.

## Канал действий

### Что проверка входа принимает

Секция «Канал действий» профиля. Из словаря канала проверке входа адресованы два глагола, остальные её
загрузчик не примет: правило, которое не сработает никогда, — опечатка, а не политика.

| Глагол | Что делает | Ограничение |
| --- | --- | --- |
| **Прервать сессию** | целая сессия уходит на форму входа, как будто её нет: это вход заново, а не продление | отправитель может быть любым — это ужесточение |
| **Пропустить без проверки** | клиент проходит без пользователя, заголовки перезаписываются пустыми | только с именем отправителя — это послабление |

**«Свежесть входа»** — защита от карусели. Отправитель шлёт сигнал на каждом запросе и не знает,
что вход уже случился; сессия моложе этого срока считается только что подтверждённой, и сигнал на
неё не действует. Умолчание — пять минут, ноль выключает отсечку.

Правила приёма — разрешающий список: срабатывает любое совпавшее, порядка и перетаскивания у них
нет. Нет правил — проверка входа никого не слушает, и это обычное состояние.

### Что проверка входа говорит сама

Проверка входа знает о клиенте то, чего не знает никто другой: вошёл ли он и кто он. Секция «Правила»
отдаёт это соседям и маршруту.

| Когда | Что дойдёт |
| --- | --- |
| **вошёл** — сессия цела и допуск есть | что угодно: сигнал соседу, событие маршрута, баллы, набор |
| **инспектор перегружен** — очередь не ниже порога ([«Когда инспектор перегружен»](06-inspectors.md#когда-инспектор-перегружен)) | что угодно, но на сброшенном запросе модуль исполнит только свои глаголы |
| **аноним** — куки нет вовсе | только событие маршрута — журнал, архив, маркер, баллы — и запись в набор |
| **сессия недействительна** — истекла, отозвана, чужая сеть или источник | то же |
| **вошёл не в ту дверь** — группы допуска нет | то же |

Ограничение трёх последних — не стиль, а физика канала: блокировка и редирект обрывают фазу, поздних волн
не будет, и сигналу соседу оттуда не уйти. Глаголы записи исполняет модуль, и блокировка для них
главный случай.

Событие — **про клиента, а не про вердикт**: под пассивным вызовом аноним остаётся анонимом, и его
правила срабатывают так же.

Сценарий, ради которого это заведено: «вошедшим капчу не показывать и классификатор не вызывать» —
прежде он собирался только условием на маршруте по куке, теперь это две строки профиля.

Запись в набор публикуется на каждом срабатывании: аноним ходит каждым запросом, и каждый такой
запрос продлевает срок записи. Памяти «уже записано» у проверки входа нет: если запись должна прекратить
повторы, набор ставят перед проверкой входа.

«Кого» у записи — те же четыре пункта, что у всех отправителей: адрес, самый узкий анонс, все
накрывающие анонсы или система целиком ([«Правила обработки трафика»](06-modsec.md#кого-писать-в-набор)).
Анонсы и состав системы проверка входа спрашивает у справочника гео установки; справочник нужен и молчит —
ответ «не смог» (`AUTH_GEO_UNAVAILABLE`), исход выбирает маршрут.

## Как настроить внешний способ

1. Завести источник, выбрать способ и заполнить его секции. Для сессии приложения заранее создать
   активный набор строк в разделе данных.
2. Завести профиль на этот источник. Форма профиля тоже знает про способ: у внешних источников она
   не спрашивает, как показать форму, а редирект предлагает только когда у источника задана страница
   входа приложения.
3. Объявить инспектора с этим профилем — «Конфигурация → http», секция «Инспекторы» — и позвать имя
   на маршрутах.
4. Для сессии приложения инспектор ставится **ещё и на фазу ответа** маршрута входа, а сам маршрут
   обязан копировать тело запроса и заголовки ответа — иначе подсматривать нечего.
5. Разослать канал `auth` и издать конфигурацию nginx.

## Что видно в событии

При любом способе проверка входа на каждом пропуске называет модулю сессию, и модуль кладёт это в запись —
блок **«Сессии»** карточки события: источник, вид (своя, JWT, приложения), логин, идентификатор и
пометки. Подробнее — [«Сессии»](08-events.md#сессии).

Личность в журнале — пара «источник:логин»: пространство имён задаёт источник входа, и `alice` своей
проверки входа с `alice` из чужого токена журнал не смешивает. Этой парой он показывает сессию, ею же
группирует и её принимает фильтр.

Идентификатор — **не сама кука**: у своей сессии это её номер, у JWT — поле токена либо отпечаток, у
куки приложения — хеш. Сырой секрет в журнал не попадает.

Находки инспектора:

| Находка | Когда |
| --- | --- |
| `auth-no-session` | куки нет вовсе |
| `auth-session-bad` | кука есть, но не годится: не разбирается, истекла, чужая сеть или источник |
| `auth-session-revoked` | сессия завершена: записи в наборе нет |
| `auth-forbidden` | вошёл, но группы допуска нет |
| `auth-unknown-profile` | на маршруте имя профиля, которого инспектор не знает |
| `auth-list-unavailable` | набор активных сессий недоступен |
| `auth-store-unavailable` | недоступно хранилище процесса |

## Когда инспектор отвечает «не смог»

`error` — «проверить не смог». Что делать с таким запросом, решает маршрут: класс `inspector` в
«Сбоях проверок», по умолчанию `deny`. См.
[«Волны, дедлайн и счёт»](05-protection.md#волны-дедлайн-и-счёт).

| Код | Что случилось | Куда смотреть |
| --- | --- | --- |
| `AUTH_UNKNOWN_PROFILE` | на маршруте имя профиля, которого проверка входа не знает | опечатка в объявлении, канал не применён — либо поколение не применилось целиком из-за дубля формы или куки |
| `AUTH_LIST_UNAVAILABLE` | набора активных сессий не видно | keeper, шина, зеркало набора |
| `AUTH_STORE_UNAVAILABLE` | хранилище процесса недоступно | Redis инспектора |
| `AUTH_QUEUE_LIMIT`, `AUTH_DEADLINE_EXCEEDED` | очередь полна или запрос простоял дольше бюджета | реплик мало для этого темпа |

Отдельно стоит знать про **дубли**: форма и кука уникальны на источник. Два источника с одним
адресом формы или одной кукой роняют поколение целиком, и симптом при этом обманчивый — только что
заведённый профиль отвечает «неизвестный профиль». Имя дубля пишется в журнал процесса проверки входа.

## Типовые задачи

### Закрыть админку группой

1. Убедиться, что общая проверка входа уже стоит и люди через неё входят.
2. Завести **второй профиль на тот же источник**, в секции «Допуск» назвать группу.
3. Объявить второе имя того же процесса с этим профилем.
4. Поставить его на маршрут админки — тот должен быть длиннее и раньше общего.

Второй формы не нужно: источник общий, человек уже вошёл. Чужой по группе получит 403, а не форму.

### Закрыть API без редиректов

1. Второй профиль на тот же источник.
2. Список методов, которым показываем форму, оставить пустым.
3. Назвать ответ блокировки — им ответит nginx.

Обычно этого не требуется вовсе: флажок «Только HTML» уже отдаёт 401 всему, что не запрашивает страницу.
Спутник нужен для клиентов, которые тащат `Accept: text/html`, оставаясь фоновым запросом.

### Не показывать капчу вошедшим

1. В профиле проверки входа — правило: «когда: вошёл» → «кому: капча» → «Пропустить без проверки».
2. У капчи — правило приёма от этого имени проверки входа.
3. Проверить, что проверка входа стоит на том же маршруте **раньше** капчи по волнам.

### Завершить чужую сессию

Открыть набор активных сессий в «Данные → Списки» и удалить запись. Повод записи несёт логин — видно,
чью сессию завершаешь. Со следующего запроса эта кука не действует нигде в установке.

## Ограничения

- **Провайдер у источника один.** Пароль плюс код — это два источника и две проверки входа на маршруте,
  связанные полем «Личность из источника».
- **Форма и кука уникальны на источник,** и дубль роняет всё поколение, а не одну запись.
- **Группы — снимок на момент входа.** Вычеркнутый из группы сохраняет доступ до следующего входа;
  мгновенно его отнимает только завершение сессии.
- **Списка публичных путей у проверки входа нет:** путь открывают тем, что не вызывают на нём инспектора.
- **Просьба соседу уходит только с события «вошёл»** — остальные три обрывают фазу.
- **Заголовки пользователя выставляются всегда, даже пустыми,** и на маршрутах без проверки входа приложение
  доверять им не должно.
- **Алгоритм `none` у чужого JWT — не защита,** а атрибуция для журнала.
