# Установка

Контроллер ставят вместе с контуром: он раздаёт конфигурацию узлам и инспекторам и без них
бесполезен. Обычно его поднимает фундамент установки (`placitum-core`); здесь — что ему нужно,
чем это называется и как проверить, что он встал.

## Что нужно рядом

| Компонент | Обязателен | Зачем |
| --- | --- | --- |
| PostgreSQL | да | конфигурация: пространства, серверы, маршруты, профили, черновики |
| NATS с JetStream | да | KV, через который поколения уезжают на узлы и инспекторам |
| Redis: внутренний | да | блобы поколений: в KV едет указатель, тело лежит здесь |
| `crypto` | при сертификатах из панели | расшифровка приватных ключей ключом контура; сам контроллер открытого текста не видит |
| `search` (логгер) | для журнала и инцидентов | панель ходит в него через контроллер, наружу он не торчит |
| `geo` | для карточек адреса | страна и ASN по адресу |

Плоскость управления может лежать без вреда для трафика: узлы работают по последней применённой
конфигурации.

## Переменные

| Переменная | По умолчанию | Что |
| --- | --- | --- |
| `CONTROLLER_PORT` | `8080` | порт API и панели |
| `CONTROLLER_DATABASE_URL` | — | `postgres://пользователь:пароль@хост:5432/база` |
| `CONTROLLER_NATS_URL` | `nats://127.0.0.1:4222` | шина; реквизиты — `CONTROLLER_NATS_USER`, `_PASS`, `_TOKEN` |
| `CONTROLLER_REDIS_URL` | — | обменник: контроллер туда не пишет, но печатает его адрес в конфиг узлов |
| `CONTROLLER_REDIS_INTERNAL_URL` | — | внутренний Redis: блобы поколений |
| `CONTROLLER_CRYPTO_SERVICE_URL` | — | `http://crypto:8093` |
| `CONTROLLER_CRYPTO_PUBLIC_KEY` | — | файл с публичной половиной ключа контура |
| `CONTROLLER_SEARCH_URL` | — | `http://search:8091` |
| `CONTROLLER_GEO_URL` | — | `http://geo:8092` |
| `CONTROLLER_UX_DIR` | `/app/ux/dist` | собранная панель в образе |
| `CONTROLLER_SCHEMA_DIR` | `/app/schema` | схема базы в образе |
| `CONTROLLER_COMPILE_DIR` | `/app/data/compile` | куда компилятор кладёт собранные конфигурации |
| `CONTROLLER_LOG` | `info` | уровень журнала |

Адрес шины, который контроллер печатает в конфигурацию узлов, берётся из его собственного
окружения, а не из сохранённого документа: сохранение документа не должно менять то, куда
ходит контур.

## Первый запуск

1. **Поднять Postgres** и дать контроллеру `CONTROLLER_DATABASE_URL`.
2. **Схема.** На пустой базе её кладёт поставка (`schema/01-baseline.sql` и `02-shipped.sql`);
   в установке, где Postgres поднимает фундамент, это делается его шагом. Живую базу пока
   догоняют руками — накатчик в работе.
3. **Ключ контура.** Публичная половина монтируется контроллеру
   (`CONTROLLER_CRYPTO_PUBLIC_KEY`), приватная — только `crypto` и агентам узлов.
4. **Панель** открывается на `CONTROLLER_PORT`. На свежей установке в ней одно пространство
   `default`, каталог инспекторов и профили поставки; серверов и маршрутов нет — их заводит
   оператор.
5. **Каталог гео** (страны и ASN) заливается отдельно: выгрузка MaxMind лицензируется сама по
   себе и в образ не едет.

## Docker Compose

```yaml
services:
  controller:
    image: placitum/controller
    ports: ["8080:8080"]
    environment:
      CONTROLLER_DATABASE_URL: postgres://waf:waf@postgres:5432/waf
      CONTROLLER_NATS_URL: nats://nats:4222
      CONTROLLER_REDIS_URL: redis://redis:6379
      CONTROLLER_REDIS_INTERNAL_URL: redis://redis-internal:6379
      CONTROLLER_CRYPTO_SERVICE_URL: http://crypto:8093
      CONTROLLER_CRYPTO_PUBLIC_KEY: /run/secrets/waf_node_pub
      CONTROLLER_SEARCH_URL: http://search:8091
      CONTROLLER_GEO_URL: http://geo:8092
    secrets: [waf_node_pub]
    depends_on: [postgres, nats, redis-internal]
```

## Проверка после запуска

```sh
curl -fsS http://127.0.0.1:8080/healthz

# Панель отдаётся тем же процессом
curl -fsS -o /dev/null -w '%{http_code}\n' http://127.0.0.1:8080/

# База отвечает и схема на месте
psql "$CONTROLLER_DATABASE_URL" -c "select count(*) from waf_schema_log"
```

В панели на свежей установке: раздел «Конфигурация» с пустым деревом, каталог инспекторов из
десяти процессов, профили `default` у каждой подсистемы. Если панель показывает жёлтое
предупреждение про отпечаток ключа — образ собран без `VITE_CONTOUR_FINGERPRINT`, сверка
публичного ключа в браузере выключена.

## Обновление

Обновление образа приносит и новую схему. Пока накатчика нет, порядок такой: применить новые
файлы `schema/migrations/1NN_*.sql` к базе, потом поднять новый образ. Когда накатчик появится,
порядок станет обратным и единственным: поднять образ, он накатит сам.

Миграции идут только вперёд: откат образа назад схему не откатывает.

## Грабли

- **Отпечаток ключа зашивается на сборке.** Сменили ключ контура — пересоберите образ, иначе
  панель будет ругаться на несовпадение.
- **Конфигурация в памяти процесса.** Правка в базе руками не видна до перезапуска: контроллер
  держит состояние в памяти и пишет в базу, а не читает её на каждый запрос.
- **`:8091` и `:8093` наружу не выставляют.** В поиск и `crypto` ходит контроллер, не браузер.
